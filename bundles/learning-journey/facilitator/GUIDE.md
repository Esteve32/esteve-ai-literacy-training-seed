# Facilitator guide — keep out of the learner AI context

Purpose: observe how a participant operates an AI and adapts an instruction recipe, not infer intelligence, attention, diagnosis or job suitability. This prototype is not a psychometric instrument. Explain the learning purpose before beginning. Facilitator presence changes behaviour; record interventions.

## Consent before observation
Agree separately: participation; live observation; private note-taking; screen sharing; audio/screen recording; later reuse. No automatic logging, camera/microphone access, analytics service or consent database is installed. A chat choice to be observed is not recording or publication consent. Do not start recording by default. Use an approved private destination, retention/deletion plan and pseudonymous session code if notes are agreed. Do not upload notes, chats, names or voice samples to this public repository or include them in future packs. Respect withdrawal and requests to stop; do not promise platform data deletion you cannot perform. Work-account and employer policies govern data use.

## Before the session
1. Note pack/version/hash, exact AI product, client/browser and any relevant tenant restrictions only if known. Plan 15–25 minutes, allow breaks; no timed test.
2. Extract the distribution ZIP. Upload only START-HERE.txt, then use ACTIVATE.txt. If blocked, paste START-HERE.txt. Do not use remote computer control or ask the learner to bypass security.
3. Keep the observation sheet on your own approved device or paper. The AI does not see the sheet. Use synthetic case material. Let the learner choose typing/dictation; never require voice where unavailable, uncomfortable or inappropriate.
4. Test that Stop and a free-text answer work. Do not announce capability success before it is evidenced.

## What to observe
| Construct | Record an action, not a judgement | Evidence label |
| --- | --- | --- |
| Voice vs typing | Visible use of microphone/keyboard; a mode switch; correction of a recognised word | Directly observed, self-report or Unknown |
| Reading/instructions | Requests a repeat; refers to a stated fact; skips a menu; asks what a word means | Exact action or agreed minimal quote, not “poor reader” |
| Tick boxes vs own words | Attempts to click static boxes; answers with letters; supplies a sentence; rejects the menu | Note interface type and phase |
| Steering | Requests a specific change; overrides a suggestion; asks for evidence; corrects an assumption | Spontaneous before prompt, prompted, assisted or skipped |
| Recovery | Notices a blocked upload or wrong interpretation; uses fallback; seeks help | Product limitation vs instruction issue vs Unknown |
| Transfer/composition | Edits a rule; checks unchanged facts; loads a handover in a new chat | Distinguish card generated from transfer actually completed |

Do not infer input modality from punctuation or polished text. Do not infer that slow replies mean poor comprehension. The AI cannot see local actions unless a separately authorised capability is actually present; this pack grants none. An optional learner preference answer is self-report, not observed behaviour.

## Session phases and bias
- J2 first attempt: allow an independent brief before supplying prompt templates. Help if asked; mark assisted. Do not leave someone stuck for measurement.
- J3–4 guided calibration/comparison: menu and own-words practice are coaching. Record order, language, device limits and whether the facilitator supplied the words. Choice order is not randomised; do not claim a causal comparison of interface performance.
- J5 evidence challenge: openly labelled unsupported practice claim. This is prompted challenge, not evidence of spontaneous scepticism. Never make a deceptive factual error in normal copy to “catch” the learner.
- J6 composition: check whether they can explain what changed; optional, not pass/fail.
- J7 transfer: if a second chat is used, verify it actually resumed; otherwise leave pending.

Use “What would you like to try?” rather than directing every response. If support is needed, offer it and record it. Note a helpful design change, not a deficit label. Do not aggregate, rank or publish observations without a separate approved method and consent.

## Debrief and improvement
Ask which input/choice mode they preferred, which instruction was unclear and one change they would make. Mark these as self-report. Compare the task outcome to their own stated goal, not other people. With permission, turn a non-identifying issue into an upgrade proposal with reproduction steps. Preview the instruction patch and retest; never copy real participant transcripts into the shared skill. Blank worksheet: OBSERVATION-TEMPLATE.md. Behavioural scenarios: ../tests/BEHAVIOUR.md.
