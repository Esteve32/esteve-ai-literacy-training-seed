# Build a portable organisational knowledge kit

Read COMMON.md and the bundled AI Literacy behaviour source. In a generated single-prompt export both are included. Apply them to the bounded task, not to unrelated accounts or settings.

## Scope and inputs

Treat this as a reusable knowledge-kit scaffold, not the complete Arbora SEED export. Obtain organisation/purpose, local machine-schema repository and verified commit if available, human field-guide source, intended audience, local database/tool map, owner, allowed destinations and privacy/release boundaries.

## Procedure

1. Inventory authorised sources and state their capture times, status and rights. Separate authoritative machine definitions, human explanations, proposals and snapshots. If the machine repository/commit cannot be verified, mark the gap; do not claim a current canonical release.
2. Build a glossary with distinct human names and stable machine names (snake_case where the local convention requires it). Explain terms rather than demand another organisation adopt Arbora's Forest/team/DB taxonomy.
3. Organise fields into identity; ownership; workflow; time; relations/context; metadata/audit. Maintain explicit aliases from local configured names to intended concepts. Do not migrate schemas or invent options from this scaffold.
4. Distinguish source evidence, source-linked observations, small reusable facts and bounded derived signals. Keep calculations/source uncertainty visible; no invented validation or hidden scores.
5. Document local work hierarchy and separate Parent (structure) from dependency/Blocked by (timing). Describe source precedence, human gates, accountable stewardship and recovery.
6. Capture capabilities and limitations of prompting, connected workflows, supervised agents and cross-organisation systems as work contexts, never ability rankings or permission grants.
7. Package README, glossary, local-map template, source manifest, release boundaries and checksums. Exclude private people/IDs, active decisions, internal diagrams/attachments and unverified media. Rebuild after approved changes and verify links/hashes/JSON before delivery.

## Output and safety

Return a local knowledge-kit draft plus explicit OPEN mapping/authority/rights fields. Use map-template.json as a starting point. Mark runtime adoption, human traversal, security and publication checks separately. Evidence of a valid archive is not evidence of a verified machine schema or production installation.

The original SEED internal archive, private schemas/records, media and publication approvals are not included. Do not claim this generic scaffold supersedes the source field guide or can be publicly released under the source's internal approval.
